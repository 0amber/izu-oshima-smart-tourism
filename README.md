**「大きなキャリーケースを持った旅行者でも、伊豆大島を気持ちよく回れる1泊2日プランを、バスのデータとAIで自動で作るサービス」**

## 1. なぜやるの？（3つの理由）

| 🎯 理由 | くわしく |
|---|---|
| **困っている人がいる** | フェリーで大島に着いた観光客は、大きなキャリーケースを持ったまま動くのが大変。人気の三原山（山登り）にはすぐ行けない。 |
| **データで決めたい** | 「なんとなく」ではなく、**GTFS**（バスの時刻表デジタルデータ）と**AI**を使って、正確でムダのない旅程を作る。 |
| **未来の観光を提案したい** | 東京都知事杯ODHで「これからの観光モデル」を提案する。 |

### 🚨 新しくわかった「本当に困る」証拠（✅ 確認済み）
大島バスの手荷物ルール：**無料で持ち込めるのは3辺合計1m以内・10kgまで**。それを超えるキャリーケースは**1個500円の有料**、しかも**混んでいると乗車を断られることがある**。
→ 「荷物を持って三原山に行く」のはお金も手間もリスクもある、という一次ソースです。（出典：大島バス 手荷物規定PDF）

## 2. だれの・どんな困りごとを解決する？（エレベーターピッチ）

```
[困っている人]  伊豆大島に来た、キャリーケースなど大きな荷物を持った観光客
      ↓
[困りごと]      荷物を持ったままだと三原山などにすぐ行けない・不便・バスに乗れないかも
      ↓
[私たちの答え]  「GTFS活用 スマートモデルコース」
      ↓
[うれしいこと]  1日目は荷物を持ったままでも楽しめる「椿・花ガーデン」
                2日目はホテルに荷物を預けて「三原山」を満喫
                → ムダがなく、ストレスのない旅
```

**ふつうの乗換案内アプリと何がちがう？**
乗換案内は「A→Bに一番早く行く方法」しか教えてくれません。私たちのサービスは **「この船で着く」「荷物がある」「2日ある」という条件の中で、実際にできる旅程を組み立てて、バスの時刻表でちゃんと成立するか検証してから出す**ところが新しい点です。

## 3. 旅のプラン（1泊2日）

### 【1日目・土曜】荷物を持ったまま「椿・花ガーデン」

| 時刻 | やること | 備考 |
|---|---|---|
| 朝 | 東京・竹芝を出発（お昼のお弁当を買っておく or 船内で買う） | ✅ 夏ダイヤのジェット船は竹芝7:25 / 7:50 / 8:15発 → 大島9:35 / 9:35 / 10:00着 |
| 〜10:00 | 伊豆大島（元町港 or 岡田港）に到着 | ❓ どちらの港に着くかは**当日の天気・海の状態で決まる** |
| **10:20** | 入港地発のバスに乗る 🚌 | ✅ 三原山ライン（8月毎日運行）。運賃 港→椿・花ガーデン 300円 |
| **10:28** | 椿・花ガーデン着。園内を観光＆お弁当ランチ | 滞在 約2時間20分 |
| **12:48** | 椿・花ガーデン発のバスに乗る 🚌 | ✅ 元町港12:40発の便。**岡田港発の場合は時刻が変わるので要確認** |
| **12:58** | 三原山温泉（大島温泉ホテル最寄）着 | ✅ 停留所はホテル直結 |
| **15:00** | 大島温泉ホテル（三原山温泉）にチェックイン ♨️ | ⚠️ 12:58に荷物を預けても、午後にホテル→山頂口へ上がるバスは時刻表上なし（13:30は山頂口発の下り便）。初日午後は温泉・周辺散策に（PoCで検証済み） |

### 【2日目・日曜】身軽になって三原山へ
1. ホテルにキャリーケースを預ける
2. 身軽な状態で「三原山」の大自然へ！（三原山温泉→山頂口 バスあり）
3. 帰りは山頂口 9:30 / 13:30発 → 出港地 9:55 / 13:55着（✅ 8月ダイヤ）

## 4. やらないこと（スコープ外）

| ❌ やらない | 理由 |
|---|---|
| 1日目に三原山へ行く | キャリーケースを持っての登山は現実的でない。バスも有料・乗車拒否リスク |
| 道案内・翻訳だけのガイド | スマホやAIで代わりができる。もっと深い文化体験・知的好奇心を満たすガイドに注力 |
| ログイン、予約機能、多言語、リアルタイム運行情報、全路線対応 | ハッカソン期間では作りきれない。1コースを完璧に見せる方が勝てる |

## 7. 🏆 ハッカソンで勝つための作戦

### 審査基準は5つ（✅ 確認済み：ODH2026ガイドブック）
| 基準 | 私たちのアピールポイント |
|---|---|
| **データ活用** | GTFS × フェリー時刻 × 来島者統計 × 施設情報を**組み合わせて「荷物」という新しい軸**を作った |
| **アイデア力** | 「経路」ではなく「**条件付きの滞在計画**」。荷物という誰も扱わない変数を旅程に入れた |
| **技術力** | AIが作った旅程を**GTFSで機械的にファクトチェック**（AIのウソ旅程を防ぐ） |
| **ソーシャルインパクト** | 島の観光消費・滞在時間の増加。来島者統計で「何人が対象か」を数字で示す。八丈島・三宅島にも横展開できる |
| **サービスデザイン** | 8/22-23に**実際に歩いた一次情報**が最強の説得材料。運用は大島町・観光協会を想定 |

### 大会の流れ（✅ 確認済み）
- 本番 8/22–23 → **First Stage提出物 締切 8/23 17:00**
- 提出物：提出フォーム（各300字×約6項目）＋プレゼン資料（16:9 PDF/PPT）＋2分プレゼン動画＋デモURL or 1分操作動画（任意）
- 2分動画の収録 8/26–30（予約制） → 結果発表 9月下旬 → Final Stage・表彰式 10/17
- ❓推測：過去の都知事杯は「複数データを掛け合わせて新しい判断軸を作った作品」が多い。GTFS単発だと部門賞止まりの可能性 → **複数データの組み合わせを見せる**

### ピッチの流れ（2分動画）
1. **課題（20秒）**：港に着いた観光客、キャリーケース、坂道、2時間に1本のバス。写真1枚
2. **気づき（20秒）**：「荷物」が旅の行程を決めているのに、どのアプリも扱っていない
3. **解決（30秒）**：荷物あり/なしを入力 → GTFS×AIが1泊2日を生成 → 時刻表で検証済み
4. **デモ（40秒）**：↓の「決定的な1シーン」
5. **データと効果（20秒）**：使ったデータ一覧、年間来島者数×想定利用率
6. **現地検証と次（10秒）**：8/22-23の実測、大島町での運用、他の島への展開

### 🎬 デモの「決定的な1シーン」
**「荷物あり ⇄ なし」のスイッチを切り替えた瞬間、旅程が組み替わり、バス便（10:20発→10:28着）に時刻表と一致した✅マークが付く。**
できれば、現地で撮った「キャリーケースで椿・花ガーデンに着いた実写」を横に並べる。

### 使うオープンデータ候補
| データ | 状態 | 使い道 |
|---|---|---|
| 大島バス GTFS-JP（公共交通オープンデータセンター） | ✅ あり。取得には開発者登録＋トークンが必要 | 旅程のバス時刻 |
| 伊豆諸島・小笠原諸島観光客入込実態調査（東京都） | ✅ あり | 「何人が対象か」の数字 |
| 東海汽船の時刻表 | △ PDF/HTMLのみ（オープンデータ形式ではない） | 到着時刻のプリセット |
| 東京都オープンデータカタログの大島町データ（トイレ・施設など） | ❓ 要確認 | 拡張候補 |

**RPで実際に読み込むのは3〜4本まで**。他は「今後の拡張」として言及にとどめる。

### 落とし穴と回避策
- AI旅程が時刻表と矛盾 → **生成後にGTFSでチェック**。動画は検証済み旅程だけ見せる
- 提出締切が現地検証の当日 → **8/21までに提出できる状態にしておく**
- 「便利ツール」で終わる → 来島者統計で規模を、都民のQOL（休暇の質）に翻訳して語る
- 椿・花ガーデン休業／持ち込みNG → 代替スポットを1つ用意
- デモURLが審査中に落ちる → 静的サイト化＋バックアップ動画

## 8. 💻 PoC/RPをどう作るか

### 最小機能（これだけ作る）
- 入力3つ：**到着港**（元町／岡田／未定）・**到着時刻**（ジェット船9:35 / 10:00プリセット）・**キャリーケース有無**（宿泊は大島温泉ホテル固定）
- 出力：**1泊2日タイムライン**（バス便ごとのカード、荷物警告バッジ、運賃合計、2日目タブ）
- **スポット詳細**画面（写真・所要時間・荷物適性・最寄バス停と次発3本）

### 技術構成（少人数・1週間で動くことを最優先）
- **Cloudflare Pages ＋ 素のHTML/JS**（データベース不要）
- GTFSは事前にスクリプトで抽出 → **静的JSONとして同梱**（数十KB）
- AIの説明文を使う場合だけ Pages Functions を1本（`/api/explain`）。**AIが失敗してもテンプレ文で動く**＝AIなしでもデモ成立

### データの流れ
```
GTFS zip（ODPT）
  → scripts/build_gtfs.py：8/22・23に有効な service_id を解決、対象バス停のtripだけ抽出
  → data/timetable.json（{tripId, serviceId, routeName, stops:[{stopId, dep, arr}]}）
  → ブラウザで「バス停A→Bで、時刻T以降の最初の便」を探す（便数が少ないので単純な探索でOK）
```

### 荷物あり/なしで分かれるルール表
| スポット | 荷物なし | 荷物あり | 理由 |
|---|---|---|---|
| 椿・花ガーデン | ○ 10:28着で観光＋弁当 | ○（園内平坦） | 港から8分・300円 |
| 三原山山頂口（初日） | ○ | **×**（未舗装、バス500円有料・乗車拒否リスク） | 2日目に預けてから |
| 大島温泉ホテル | 15:00 IN | 12:58着で荷物預け → 温泉・周辺散策（午後の上り便なし） | 三原山温泉バス停直結 |
| 元町散策 | ○ | △ | 坂道 |

実装：各スポットに `luggageScore(0〜2)` を持たせ、荷物ありなら score≥1 だけ候補に残し、バス時刻順に詰める。バス手荷物500円／混雑時拒否リスクはタイムライン上に**警告バッジ**で表示。

### 画面（3画面だけ）
1. **入力**：港・到着時刻・キャリー有無トグル
2. **タイムライン**：「10:20 港発 → 10:28 椿・花ガーデン」カード、警告、運賃合計、2日目タブ
3. **スポット詳細**

### デモシナリオ（審査員に見せる順番）
1. 荷物なし → 初日に山頂まで行く案が出る
2. 同じ条件で**キャリーONに切替** → 椿・花ガーデン → 12:48便でホテル先着・預け → 翌朝三原山、と旅程が組み替わる
3. 到着港を岡田に切替 → 時刻が追従する
4. 「説明文を生成」ボタン → AIの文章が出る

### リスクと代替案
- ODPTトークン取得が遅れる → 公式PDFから起こした**手入力JSON**で開発を止めない（三原山ラインの主要便は既に抽出済み）
- 8月と9月でダイヤが変わる → ピッチ日は8月ダイヤに固定
- 港が当日変わる → 「入港地」という抽象バス停を用意して実港にマッピング
- バスで荷物拒否 → 「港のコインロッカー／ホテル直行」ルートを常に第2案として表示

### コード断片（次のバスを探す関数）
```js
// バス停from→toで、時刻t(HH:MM)以降の最初の便を返す
export function nextBus(tt, from, to, t) {
  const m = s => { const [h, mi] = s.split(":").map(Number); return h*60+mi; };
  return tt.flatMap(trip => {
    const i = trip.stops.findIndex(s => s.stopId === from);
    const j = trip.stops.findIndex(s => s.stopId === to);
    return (i >= 0 && j > i && m(trip.stops[i].dep) >= m(t))
      ? [{ trip, dep: trip.stops[i].dep, arr: trip.stops[j].arr }] : [];
  }).sort((a, b) => m(a.dep) - m(b.dep))[0] ?? null;
}
```

## 10. 用語ミニ辞典

| 用語 | 意味 |
|---|---|
| **GTFS / GTFS-JP** | バスや電車の時刻表・路線・停留所をコンピュータが読める形にした共通データ形式。JPは日本版 |
| **オープンデータ** | 誰でも自由に使っていいと公開されているデータ。行政が公開していることが多い |
| **ODH** | 東京都知事杯オープンデータ・ハッカソン。都のオープンデータでサービスを作って競う大会 |
| **ODPT** | 公共交通オープンデータセンター。大島バスのGTFSはここで公開されている |
| **PoC** | Proof of Concept。「このアイデアは本当に動くのか」を確かめるための試作 |
| **RP** | Rapid Prototype。短期間でざっくり作る試作品 |
| **MVP** | Minimum Viable Product。最小限の機能だけ持った、使える製品 |
| **Cloudflare Pages** | ウェブサイトを無料で公開できるサービス。今回の開発環境 |
| **service_id** | GTFSの中で「この便はどの曜日・季節に走るか」を表すID（例：三原山＿夏＿3） |
| **ペルソナ** | サービスを使う代表的な人物像。「初めて大島に来た、知り合いのいない、キャリーケースを持った観光客」 |
| **QOL** | Quality of Life。生活の質。ここでは「休暇の質」 |
| **ピッチ** | 短時間で審査員に企画を売り込むプレゼン |
| **一次情報** | 自分で現地に行って確かめた情報。伝聞よりずっと強い |
