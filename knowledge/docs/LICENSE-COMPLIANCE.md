# ライセンス・コンプライアンス：復元不可能性の基準

## 制約（チーム決定 D-4）

大島バスGTFS（公共交通オープンデータセンター提供）は、**加工して公開することは可能**だが、**公開した加工物から元のGTFSを復元できてはいけない**。
（一次情報：ODPTの利用規約・データセットのライセンス表示を各自確認すること。ここではチームで合意した運用基準を書く）

## 基本方針：「観光に必要な範囲だけの、不可逆な要約」

生成スクリプト（`scripts/gtfs_to_knowledge.py`）は次を守る。

### やること（残す情報）
- **選抜した停留所**（観光地・港・宿の最寄りなど、`config/oshima.json` に列挙したものだけ）の発着時刻
- 路線ごとに「上り／下り」の表。運行日区分は**文章**（例：「8月毎日」「土日祝」）で表す
- 観光に必要な運賃ペア（港〜椿・花ガーデン など、config で指定したものだけ）
- 生成日・GTFSの有効期間・出典URL

### やらないこと（落とす情報）
- GTFSの各ファイル（stops.txt / stop_times.txt / trips.txt / calendar*.txt / shapes.txt / fare_*.txt 等）の**転記・同等構造での出力**
- **全停留所・全便の網羅**（選抜停留所以外は出さない。途中停留所の時刻も出さない）
- `stop_id` / `trip_id` / `route_id` / `service_id` / `shape_id` などの**識別子**
- 停留所の**緯度経度**、路線形状（shape）
- カレンダー（`calendar.txt` / `calendar_dates.txt`）の日付列挙。→「運行日区分」の説明文に変換する
- 出力CSVの列名をGTFSと同一にすること（`stop_sequence`, `arrival_time` などは使わない）

## 復元不可能性の考え方

| 観点 | 元GTFS | 公開する要約 |
|---|---|---|
| 停留所 | 全停留所＋座標＋ID | 観光に関係する数停留所の**名前だけ** |
| 便 | 全trip＋全stop_time | 選抜停留所を通る便の、選抜停留所での時刻だけ |
| 運行日 | service_id と日付の対応表 | 「8月毎日」等の文章 |
| 構造 | 正規化された複数CSV | 人が読むMarkdown表＋観光向けの縦長CSV |

→ 公開物だけから、停留所マスタ・便の全停車パターン・カレンダー・形状は再構成できない。

## 公開前チェックリスト

- [ ] `oshima/timetable/` に stop_id / trip_id / route_id / service_id / shape_id / lat / lon の文字列が含まれていない（`scripts/check_compliance.py` で機械チェック）
- [ ] 表に出ている停留所が `config/oshima.json` の選抜リストの範囲内である
- [ ] GTFS zip・解凍したtxtがコミットされていない（`git status` と `.gitignore` 確認）
- [ ] 各ファイル冒頭に「生成日／GTFS有効期間／出典／注意」がある
- [ ] 元データ提供者（大島旅客自動車・ODPT）のクレジットを README と各ファイルに明記
