# ChatGPTへの渡し方と、旅程を頼むプロンプト雛形

## 渡すもの（2種類）
1. **暗黙知**：`knowledge/oshima/knowledge/00_index.md` と 01〜10 の各ファイル
2. **時刻表**：`knowledge/oshima/timetable/oshima-bus-timetable.md`（GTFSから生成。生成日・有効期間つき）

## 渡し方（実験して本命を決める：DECISIONS.md 未決事項）

| 方法 | やり方 | 向き・注意 |
|---|---|---|
| A. 貼り付け | 上記Markdownの中身をチャットに貼る（時刻表→暗黙知の順） | 最も確実。長くても数千字なので1回で入る |
| B. ファイル添付 | `.md`／`.csv` を添付 | CSVは「Advanced Data Analysis」で集計に向く。表の読み違いに注意 |
| C. リンクを読ませる | GitHubで公開し、READMEや各mdのURLを渡す（富山の例と同じ） | 公開先が決まってから。ChatGPTが取得できるのは公開ページのみ。GitHubの生ファイル（raw）URLの方が読みやすいことがある |
| D. カスタムGPT | Knowledgeにmd/csvを登録し、Instructionsに下記ルールを書く | チームで繰り返し使うなら便利。データ更新時に差し替え |

## プロンプト雛形（貼り付け版）

```
あなたは伊豆大島の旅程プランナーです。以下の【時刻表】と【現地の暗黙知】だけを根拠に、
時刻入りの1泊2日の旅程を提案してください。

ルール：
- バスの時刻は【時刻表】にある便だけを使う。表にない時刻・便を作らない。
- 使ったバス便は「路線／区間／発時刻→着時刻」を明記する。
- 港（元町/岡田）が未確定なら、両港で成立する便を優先し、港が変わった場合の差分を書く。
- 荷物あり／なしで行程を分け、荷物ありの時間帯は平坦でバス停に近い場所を選ぶ。
- 帰りは船の時刻から逆算して「港に着く最後のバス」を先に固定する。
- 未確認事項（宿の荷物預かり、園内の飲食可否など）は「要確認」と明示する。

条件：
- 日程：8/22（土）〜8/23（日）、一人旅
- 往路：ジェット船 竹芝7:50発 → 大島9:35着（港は当日決定）
- 復路：8/23 大型客船 大島14:20発（要確認）
- 宿：大島温泉ホテル（三原山温泉バス停前）
- 荷物：大きなキャリーケースあり
- 行きたい：椿・花ガーデン、三原山

【時刻表】
（oshima-bus-timetable.md の内容を貼る）

【現地の暗黙知】
（00_index.md と 01〜10 の内容を貼る）
```

## 結果の確認ポイント（持ち寄り用）
- 提示された全バス便が時刻表に実在するか（列と時刻が一致）
- 「午後にホテル→山頂へ上がる便」を勝手に作っていないか
- 帰りの船に間に合う港着便を使っているか
- 荷物ありの初日に三原山へ行かせていないか
- 要確認事項を要確認と書いているか

各自の試行結果は `knowledge/docs/EXPERIMENTS.md`（作成予定）に「渡し方／プロンプト／結果の良否／気づき」を追記する。
