## 使い道
1. **First Stage収録（フォーム6-2、Zoom）**：この映像を画面共有で流しながら下の台本を読む（2分）。事務局は「音声を利用する作品以外は無音」なので、映像自体は無音のまま
2. **3-8 デモの操作動画（任意・60秒以内・無音）**：`record_promo.py` の TIMELINE を PoC 実演40秒＋前後だけに絞れば60秒版が作れる
3. チーム・審査員向けの共有（Messenger/Slack）

## ナレーション台本（約120秒・約560字。映像のタイムラインに合わせてある）

| 秒 | 画面 | 読み上げ |
|---|---|---|
| 0–8 | 表紙 | SBC.別班連携チームの「大島スマートコース」です。キャリーケースがあっても、伊豆大島を楽しみ尽くす。AIが読める交通・観光ナレッジと、その実証デモを提案します。 |
| 8–24 | 課題（500円/15:00/未舗装） | 港に着いた瞬間、旅は荷物に縛られます。大島バスでは大きな荷物は1個500円、混雑時は乗車を断られることも。宿のチェックインは15時。三原山の遊歩道は未舗装で、キャリーケースでは行けません。 |
| 24–36 | 乗換案内は荷物を知らない | 生成AIに旅程を頼んでも、バスの時刻入りの提案は返ってきません。時刻表はPDF、GTFSはzipで、AIが読めないからです。必要なのは「経路」ではなく、荷物・2日間・この便で着く、という制約付きの滞在計画です。 |
| 36–76 | PoC実演 | そこで、公共交通オープンデータGTFSを、観光に必要な停留所だけの「AIが読める時刻表」に変換し、現地の暗黙知と一緒に渡します。実演です。港・到着時刻・荷物の有無を選ぶだけ。荷物ありなら10時20分の便で椿・花ガーデンへ、12時48分の便でホテルへ。身軽に切り替えると、山頂口へ直行。2日目は荷物を預けて山へ上がり、13時37分の最終便で港へ。すべて実在する便で、時刻表と一致マークが付きます。 |
| 76–90 | 仕組み | 生成AIは説明文だけを担当し、旅程はGTFSで機械的に検証するので、存在しない便を作りません。港が当日変わる島の事情も吸収し、単一HTMLでオフラインでも動きます。 |
| 90–102 | オープンデータ | 使ったデータは、公共交通オープンデータセンターの大島バスGTFS-JP、東京都の観光入込調査など。GTFSの加工物は元データを復元できない要約に限定し、ライセンスに配慮しています。 |

| 112–120 | 検証と次のステップ | 旅程は公式時刻表と突き合わせて机上検証済み。今後はGTFSからの自動生成とGitHub公開、大島町・観光協会との運用相談へ進めます。ご清聴ありがとうございました。 |
